# 10. Потоки і пікер (SAF)

> Актуально: 2026-07. Найдорожчий урок проекту — тут.

## Головне правило потоків
`on_activity_result` у p4a викликається з **Java-потоку Android**, НЕ з
Kivy-потоку. Наслідки порушення (все спостерігалось наживо): модалки не
зʼявляються, бейджі без цифр, списки з «застряглими» рядками, чорний екран
2–3с (важке I/O блокує main thread). Дані при цьому цілі — бреше лише UI.

**Канон:** важка робота (копіювання content://, екстракція тексту) — у
`threading.Thread(daemon=True)`; ВСІ UI-колбеки — `Clock.schedule_once`;
фоновий потік після Java-обʼєктів — `jnius.detach()` (хелпер `_detach_jni`).
Схема процесу — [[12_Схеми_процесів]] §6.

## doc_picker.py — контракти
- `is_available()` — True лише в справжньому APK (ANDROID_ARGUMENT +
  імпорти android/jnius). У Pydroid SAF не працює (чужа activity).
- `pick_document(dest_dir, on_picked, on_error)` — одиничний.
- `pick_documents(dest_dir, on_picked, on_error, mime_types=None)` —
  множинний (EXTRA_ALLOW_MULTIPLE; getClipData АБО getData). on_picked
  отримує список пар (local_path, display_name). Обидва колбеки — вже
  в Kivy-потоці (Clock всередині пікера).
- Помилки: doc_picker_unavailable / doc_pick_cancelled / doc_read_error
  (= ключі локалізації).

## Захисти пікера
1. **busy-гейт** `_busy`: SAF відкривається з лагом до ~1с; повторний тап
   стартував ДРУГИЙ пікер поверх (звідси «кілька разів назад щоб закрити»).
   Поки перший у польоті — нові виклики тихо ігноруються; `is_busy()` для UI.
2. **Порядок у _on_result**: спершу перевірка request_code (чужі результати
   ігноруються БЕЗ unbind — інакше свій результат губився і діалог зависав),
   unbind лише для свого, потім скидання _busy.
3. Копія `_unique_path` (name (1).ext) — перезапису немає; replace-семантику
   робить викликач ([[09_Документи_три_контури]]).
4. `_copy_uri_to_file` — потокове читання openInputStream у bytearray
   (позначено # Claud TUNE — єдине місце, чутливе до версії pyjnius).

## Системне, що НЕ лікується кодом
DocumentsUI на частині прошивок першим «назад» згортає бокову панель/пошук
і лише другим закривається — це поведінка пікера, не наша.
