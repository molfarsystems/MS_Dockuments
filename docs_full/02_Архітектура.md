## Базові патерни (обовʼязкові до наслідування)

### Async-патерн менеджерів БД
Кожна операція: воркер-`threading.Thread(daemon=True)` → власне зʼєднання
sqlite (`_connect()` з PRAGMA зі `schemas.apply_pragmas`: WAL, FK,
busy_timeout=5000) → результат в UI ЛИШЕ через `Clock.schedule_once`.
Спільного conn між потоками НЕМАЄ. Текст помилки фіксується ДО планування
лямбди (`msg = str(e)`) — див. [[13_Уроки_і_патерни]] §2.

### Токен раунду + життєвий цикл екрана
`project_chat_screen`: кожен раунд отримує інкрементний токен; колбеки
перевіряють `_is_current(token)` і `_screen_active`. Вихід з екрана інвалідовує
раунд — «мертві віджети» не оновлюються. APIManager гарантує РІВНО ОДИН колбек
(state.settled + watchdog) — [[05_Провайдери_і_API]].

### Делегатори
Великий екран делегує логіку модулям: подача документів слота →
`meeting_docs.build_slot_docs_block` (екран передає query+kb, три місця виклику
не знають про гібрид); парсер черги → `meeting_queue`. Нову логіку — так само
в модулі, екран лишається диригентом.

### Whitelist для динамічного SQL
Імена таблиць — тільки через `TABLE_MAP`/`ROLES_TABLE_MAP`; значення — тільки
параметрами. f-string у SQL дозволений ЛИШЕ для whitelist-імен.

### Єдине джерело правди
- SQL-схеми, версії, PRAGMA, промпти місць → `modules/schemas.py`
- ВСІ ліміти документів (3 контури) → `modules/doc_parser.py`
- Реєстр провайдерів → `tools/providers_registry.py`

### Стійкість пакета адаптерів
`tools/ai_adapters/__init__.py`: `ADAPTER_REGISTRY` і `get_adapter` визначаються
ЗАВЖДИ; кожен адаптер реєструється в try — падіння одного не валить пакет.
Це критичне обмеження збірки, не стиль.

## Точка входу (main.py)
1. Ранній логер імпортів `_early_log` → molfar_import.log (обрізка 256КБ);
   збій імпорту → аварійний екран з трейсбеком.
2. `MainApp.build()`: Lang → ConfigManager → KV root (preloader + екрани +
   drawer) → portrait lock → immersive sticky → інсет статус-бара →
   `_patch_modal_inset` (той самий інсет для всіх ModalView).
3. `Clock +0.5с → _init_db → creator.initialize()`: резолв базової теки,
   підтеки, 5 БД (+knowledge.db створює ArchivistDB сам), сиди, менеджери
   на app: `db_manager, chat_db_manager, ai_config_manager,
   participants_manager, memory_manager, roles_manager, archivist_db`.
4. Прелоадер ≥1.2с → home. Помилка БД → MDDialog обмеженого режиму.
5. Drawer: `sm.bind(current=left_menu.update)` + оновлення «Нещодавніх» на
   кожне відкриття (бінд на `status`).
