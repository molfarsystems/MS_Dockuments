# 01. Концепція і термінологія

> Актуально: 2026-07.

## Що таке Molfar System
Android-застосунок для **AI-конференцій**: кілька AI-учасників на різних моделях
і провайдерах (Google Gemini, NVIDIA NIM, OpenRouter) спілкуються в межах проекту.
Розробляється з телефона; APK збирається через GitHub Actions. Основний користувач —
автор; закладено перспективу дистрибуції (5 мов, ліцензійні межі провайдерів).

## Сутності

### Проект
Контейнер роботи. Активні типи: `conference`, `meeting`, `orduino`.
Тип `quick` — «нежить»: прибраний з UI, лишився в схемі/TABLE_MAP для сумісності
старих БД (доля — у [[16_Беклог]]). Кожен тип — окрема таблиця в projects.db
(whitelist `TABLE_MAP` проти SQL-інʼєкцій через f-string).

### Слоти 1–6
- **1–4 — робочі учасники**: кожен має провайдера, модель, роль (промпт+скіл)
  і документи (до `SLOT_MAX_DOCS` з пулу проекту). У раунді відповідають
  паралельно й незалежно, не бачачи один одного.
- **5 — Оркестратор (модератор)**: синтезує відповіді раунду, веде прямий діалог,
  формує чергу адресних питань, користується довготривалою памʼяттю проекту.
- **6 — Секретар/Архіваріус**: відповідає ЛИШЕ по вмісту документів проекту
  (через двигун знань) і складає офіційний протокол. У раундах участі не бере.

### Раунд
Питання користувача → паралельно учасникам 1–4 → Оркестратор синтезує підсумок
і пропонує нумеровану чергу follow-up питань. **Адресне привселюдно** — питання
одному учаснику, відповіді бачать усі (спільна стенограма). Раунд 2 = виконання
черги + фінальний синтез. Деталі: [[12_Схеми_процесів]].

### Гайдук
Одиночний чат «Швидкі запитання» (`mod/pop_ai.py`): вибір моделі з усіх
провайдерів, накладні ролі, документи сесії (5 файлів / 1 МБ / 5.5 МБ, гібридна
подача), експорт .txt, діалог «Експорти чатів». Памʼять — окремі таблиці
haiduk_* у chat_history.db; документи сесії гинуть разом із памʼяттю («вайп»).

### Ролі
Каталог «спеціалістів» двох видів: **для учасників** і **для оркестраторів**.
Роль = промпт + скіл. Builtin-ролі сідяться з `roles_seed.py`, кожна дзеркалиться
у файли `Roles/{slug}_{id}_{hash6}/prompt.md, skill.md`. Див. [[07_Ролі_і_памʼять]].

### Місця (places)
Системні промпти «посад», зашиті в `schemas.py` і сідяться в ai_config.db:
`orch_composite`, `orch_direct` (Оркестратор), `archivist_place`,
`archivist_protocol` (Секретар), база Гайдука (`HAIDUK_PLACE_BODY` в pop_ai).
Роль користувача накладається ПОВЕРХ місця.

### Довготривала памʼять
memory.db: факти/рішення/задачі проекту (категорії, importance 1–10, pinned).
Оркестратор витягає релевантне перед синтезом і зберігає суть раунду після.

### Двигун знань (Архіваріус)
knowledge.db: документи (файл або веб-джерело) → чанки (~1000 символів,
перекриття 150) → LIKE-пошук по `text_norm` (casefold) → ранжування → TOP-N.
Scope: (project_id, project_type); Гайдук живе в scope `(0, "haiduk")`.
Повністю перебудовна БД. Див. [[08_Двигун_знань]].

### Пул документів проекту
Спільні файли проекту (project_documents + тека Documents/<Тип>/<id>_<дата>).
Слоти отримують ПОСИЛАННЯ на файли пулу (не копії). Три контури лімітів —
[[09_Документи_три_контури]].

## Словник
| Термін | Значення |
|---|---|
| p4a | python-for-android, тулчейн збірки APK |
| SAF | Storage Access Framework, системний пікер файлів |
| таб / таб-екран | екран наради `project_chat_screen` з вкладками Інфо+1–6 |
| вайп | «Очистити» в Гайдуку: чат + документи + індекс + тека Gaiduk/ |
| backstop | аварійний запобіжник, у нормі не спрацьовує |
| гібридна подача | малі файли повним текстом, великі — огляд+фрагменти |
| орфан-слот | слот з конфігом, який посилається на видалену модель/роль |
| «чорна скринька» | molfar_crash.log + аварійний екран старту в main.py |
