# 03. Збірка і середовища

> Актуально: 2026-07.

## Два середовища виконання
| | Pydroid 3 | APK (p4a) |
|---|---|---|
| Python | 3.13 | 3.11 |
| kivy.utils.platform | "android" | "android" |
| SAF-пікер | НЕ працює (чужа activity; `doc_picker.is_available()`=False через відсутній ANDROID_ARGUMENT) | працює |
| Шляхи | user_data_dir fallback | getExternalFilesDir |
| Призначення | швидка перевірка логіки | бойовий прогін |

Код зобовʼязаний працювати в обох: платформозалежне — за прапорцями
(`ANDROID_ARGUMENT`, try-import `android`/`jnius`), не за platform=="android".

## Критичні обмеження (НЕ ЗЛАМАТИ) і чому
1. **Лише getExternalFilesDir** (fallback user_data_dir). Scoped Storage:
   запис у корінь /storage/emulated/0/ на API 33 неможливий без спецдозволів.
   Експорт назовні — тільки через MediaStore ([[11_Експорти_і_завантаження]]).
2. **Стійкий `ai_adapters/__init__.py`** — див. [[02_Архітектура]]; збій
   одного адаптера (напр. відсутня залежність у p4a) не має вбивати всі.
3. **SQLite без FTS5** — модуль не зібраний у p4a. Пошук: LIKE по
   нормалізованій колонці `text_norm` (casefold) з ESCAPE. MATCH/bm25 — заборонені.
4. **requests лише всередині методів** — module-level імпорт на старті p4a
   випадково ламався/сповільнював холодний старт; правило зафіксоване.
5. **Потоки**: `on_activity_result` = Java-потік ([[10_Потоки_і_пікер]]);
   віджети — тільки з Kivy-потоку.

## buildozer.spec — важливе
- p4a v2024.01.21, bootstrap sdl2, archs arm64-v8a+armeabi-v7a,
  android.api 33 / minapi 24, build-tools 33.0.2.
- requirements: python3, kivy==2.3.0, kivymd==1.2.0, requests, certifi,
  charset-normalizer, idna, urllib3, pyjnius, pillow, pypdf.
- source.include_exts містить py,kv,ini,json,md,png,jpg — тому lang/*.ini і
  faq потрапляють в APK автоматично.
- Іконки/presplash: assets/icons (adaptive icon для API 26+).
- WRITE_EXTERNAL_STORAGE лишений для legacy-запису Download на API 24–28
  (на 29+ no-op).

## CI (GitHub Actions)
Пуш → buildozer у контейнері → артефакт APK. Цикл розробки: пакет правок →
заміна файлів у репо → збірка → тест на пристрої за чеклістом
([[15_Тест-чеклісти]]) → скріншоти/лог назад в аналіз.

## Діагностика на пристрої
- `molfar_import.log` — ранні імпорти (до Kivy).
- `molfar_crash.log` + екран «ПОМИЛКА СТАРТУ MOLFAR» — краші run() з кнопкою
  «Копіювати у буфер».
- `_debug_beacon` (creator) — ТИМЧАСОВИЙ маячок шляху; у беклозі на видалення.
- Снекбари з цифрами (індексація N/N) — швидка польова діагностика без logcat.
