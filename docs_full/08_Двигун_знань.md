# 08. Двигун знань (Архіваріус)

> Актуально: 2026-07 (knowledge.db v3).

## Два шари
- `modules/archivist_db.py` — низькорівневий доступ (СИНХРОННІ методи,
  зʼєднання на виклик; самодостатня БД без імпорту schemas).
- `modules/archivist_engine.py` — чиста логіка: чанкування, keywords,
  пошук з ранжуванням, фонова індексація пулу, індексація веб-результатів.

## Scope
Ключ простору = (project_id, project_type). Проекти — свої id/типи;
**Гайдук = (0, "haiduk")**. Одна БД обслуговує Секретаря, слоти наради
(гібридна подача) і Гайдука.

## Індексація
`engine.reindex_pool_async(kb, pid, ptype, docs_dir, filenames, on_done)`:
фоновий потік → на файл: extract_text (doc_parser) → sha256 →
`kb.upsert_document` (sha збігся → skip, дедуп) → `chunk_text` (~1000
символів, перекриття 150) → `kb.replace_chunks` (транзакційно; пише
text=оригінал і **text_norm=casefold** для кожного чанка) → summary
{files, indexed, skipped, errors} через Clock.
Тригери індексації: додавання в пул (авто), кнопка Секретаря,
самолікування при подачі (файл без чанків → фонова переіндексація).

## Пошук
`engine.keywords(query)`: слова ≥ MIN_KEYWORD_LEN, **casefold** (узгоджено
з text_norm; lower ≠ casefold для ß тощо).
`kb.search_rows`: SQL `text_norm LIKE '%kw%' ESCAPE '\'` (OR по ключах,
%/_ екрануються `_like_escape`) у межах scope + опц. `scope_files` —
нічого зайвого в Python не тягнеться (важливо при пулі 30 МБ).
`engine.search`: ранжування hits+щільність → TOP-N (limit; Секретар 5,
подача слотів/Гайдука 8).

## Огляди і веб
- `doc_overviews(pid, ptype, max_docs, char_cap)` — перший чанк (ord=0)
  КОЖНОГО документа: базовий вміст для запитів «виклад усіх документів»
  і для гібридної подачі великих файлів.
- Веб-джерела: результати web-пошуку провайдерів індексуються як
  documents(source_type='web', url, title, query) — фрагменти цитуються
  з позначкою [WEB]. `clear_web_sources` — політика оновлення.

## Обслуговування
- `delete_document(pid, ptype, filename)` — джерело + чанки (FK CASCADE).
- `clear_project(pid, ptype)` — весь scope (вайп Гайдука).
- `stats(pid, ptype)` — documents/chunks (+web_*) для статусу вкладки.
- Міграції: див. [[04_Дані_і_БД]]; БД можна знести — перебудується.

## Фаза 2: embedding (зарезервовано)
Поля `chunks.embedding BLOB` + `embedding_model` вже в схемі — векторизація
не потребуватиме міграції. План: embedding-API через наші ж адаптери
(Google text-embedding-004 / NIM), косинус у Python поверх LIKE-фільтра.
Стримувачі: мережа на індексацію, вартість, локальні моделі в p4a важкі.
